# UPる

C++ / OpenGL / GLUTを使用して個人制作した、縦スクロール型の2Dアクションゲームです。

プレイヤーを操作して様々な壁やギミックを攻略しながらステージを上へ登り、最上部のゴールを目指します。

プログラミングを中心に、ゲームシステム、ステージ設計、UI、演出、サウンドなどを組み合わせ、一つのゲームとして完成させることを目標に制作しました。

---

## ゲーム概要

プレイヤーは左右移動とジャンプ、壁への張り付きなどを利用してステージを上へ進みます。

ステージには通常の壁だけでなく、

- 張り付けない壁
- 滑る壁(氷壁)
- 加速壁
- 反射壁
- 加速床
- 動く壁

など、それぞれ異なる性質を持つギミックが登場します。

ギミックの特徴を理解し、何度も挑戦しながら攻略方法を見つけていくことをゲームのコンセプトとしています。

---

## 操作方法

| キー | 操作 |
|---|---|
| `←` `→` | 左右移動 |
| `Space` | ジャンプ |
| `Space` 長押し | ジャンプをチャージ |
| `Z + ←` | 左壁に張り付く |
| `Z + →` | 右壁に張り付く |
| `Enter` / `Space` | メニュー決定 |
| `ESC` | ポーズ / 前の画面へ戻る |

ジャンプはSpaceキーを長押しすることでチャージでき、チャージ量に応じてジャンプ力が変化します。

---

## 主なギミック

### 通常壁
壁に接触している状態でZキーと壁方向のキーを入力すると張り付くことができます。

### 張り付けない壁
通常の壁とは異なり、Zキーを入力しても張り付くことができません。

### 滑る壁(氷壁)
壁に張り付くことはできますが、張り付いている間も徐々に下方向へ滑ります。

### 加速壁
横から接触すると、プレイヤーを上方向へ加速させます。

### 反射壁
接触した方向やプレイヤーの速度に応じてプレイヤーを跳ね返します。

### 加速床
上から着地すると、指定された方向へプレイヤーを加速させます。

### 動く壁
一定の範囲を移動する壁です。
壁の動きとタイミングを考えて攻略する必要があります。

## 工夫した点

### 1. ジャンプチャージシステム

Spaceキーを押している時間によってジャンプ力が変化するシステムを実装しました。

単純なジャンプだけではなく、「どの程度チャージして、どの位置からジャンプするか」を考える要素を加えることで、操作に幅を持たせています。

また、最大までチャージされた瞬間に効果音を再生し、最大ジャンプが可能になったタイミングをプレイヤーが認識しやすいようにしました。

### 2. 複数の壁ギミック

同じ壁でも性質の異なる複数種類のギミックを実装しました。

壁の種類によって衝突時の処理や張り付きの可否、プレイヤーに与える速度などを変更することで、それぞれ異なる攻略方法が必要になるよう設計しています。

### 3. 衝突判定の調整

複数の壁を隙間なく配置した際、壁同士の境界部分が床として判定され、プレイヤーの移動が引っかかってしまう問題がありました。

そこで、壁の上面が別の壁によって塞がれているかを判定し、実際に露出している上面のみを床として扱う処理を追加しました。

ゲーム全体を繰り返しプレイして細かな挙動を確認し、操作を妨げる判定を修正しています。

### 4. ステージ設計

ステージは実際に何度もプレイしながら、壁やギミックの位置を細かく調整しました。

単純に難しくするのではなく、

- 初見では攻略方法を考える
- 失敗からギミックの特徴を理解する
- 操作に慣れることで少しずつ先へ進める
- 最終的にはクリアタイムを縮められる

という上達を感じられる構成を意識しています。

また、一部では複数の進行ルートを選択できるようにし、プレイヤー自身が攻略方法を考えられるようにしました。

### 5. ゲームとしての完成度

ゲーム部分だけでなく、

- タイトル画面
- HOW TO PLAY
- ポーズ
- クリア演出
- タイム計測
- ランキング
- BGM
- 効果音

なども実装し、一つのゲームとして遊べる状態まで完成させることを意識しました。

### 6. リファクタリングによる保守性・拡張性の向上

当初は、ゲームの主要な処理を `game2.cpp` にまとめて実装していました。しかし、機能追加に伴ってコードが肥大化し、処理の把握や修正が難しくなるという課題がありました。

そこで、各処理の役割を整理し、機能ごとにクラス化・ファイル分割を行いました。

- `Player`：プレイヤーの状態管理、移動、ジャンプ、アニメーション
- `Wall`：壁の種類、移動、テクスチャなどの管理
- `Stage`：壁オブジェクトの管理、配置、更新・描画
- `Ranking`：クリアタイムの記録、順位管理、ファイルへの保存・読み込み
- `Audio`：BGM・効果音の再生管理
- `Renderer`：図形や文字列の共通描画処理
- `ScreenRenderer`：タイトル、ポーズ、クリア画面などの描画処理
- `Debug`：デバッグ情報の表示、当たり判定の可視化、テレポート処理

これにより、各機能の責務が明確になり、修正箇所の特定や新しい機能の追加を行いやすい構成へ改善しました。

なお、ゲーム全体の進行管理や衝突判定など、一部の処理は引き続き `game2.cpp` で管理しており、今後も段階的な改善を進める予定です。

### 7. デバッグ機能の実装

開発中の動作確認や不具合の原因調査を効率化するため、デバッグモードを実装しました。

F3キーでデバッグモードを切り替え、以下の情報を確認できます。

- プレイヤーの座標・移動速度・状態
- カメラ座標
- ジャンプ回数・落下回数・ジャンプチャージ量
- FPS（描画回数）・UPS（更新回数）
- プレイヤー・壁・地面の当たり判定領域

また、ショートカットキーによってステージ内の指定位置へテレポートできる機能も実装しました。

テレポート時には、プレイヤーの速度やジャンプ状態、キー入力状態、カメラ位置などもリセット・更新することで、移動先での動作確認を行いやすくしています。

これにより、長いステージを最初からプレイし直すことなく、特定のギミックや衝突判定を繰り返し検証できるようにしました。

### 8. 壁・床のテクスチャ管理の改善

壁や床の視認性とステージの雰囲気を向上させるため、種類に応じたテクスチャ描画を実装しました。

`Wall` クラスでは、壁の種類に応じてテクスチャを設定できるようにし、`setTexture()` によって画像の種類と繰り返し表示するサイズを指定できる構成にしました。

また、OpenGLのテクスチャ繰り返し機能（`GL_REPEAT`）を利用し、壁の大きさに応じて画像をタイル状に描画しています。

これにより、壁のサイズごとに個別の画像を用意する必要がなくなり、さまざまな大きさの壁に同じテクスチャを再利用できるようになりました。

さらに、通常壁・張り付き不可壁・氷壁・加速壁・反射壁・加速床など、ギミックの種類に応じた描画処理を分けることで、見た目から壁の性質を判断しやすいよう工夫しました。

## グラフィックについて

本作品では、プレイヤーや背景、壁・床などに画像素材を使用し、ゲームの世界観やギミックの視認性を高めています。

一部のグラフィック素材には生成AIを活用しています。

生成された画像をそのまま使用するのではなく、ゲーム全体の世界観やステージごとの雰囲気、UIとの統一感などを考慮しながら、用途に合わせた素材の選定・調整を行いました。

### 壁・床のテクスチャ化

当初は壁や床を主に単色の図形で描画していましたが、ゲームの見た目を改善するため、通常壁・特殊壁・床にテクスチャを導入しました。

- 通常壁：木・草・石・雪など、ステージの環境に合わせた複数のテクスチャ
- 特殊壁：張り付き不可壁・氷壁・加速壁・反射壁など、ギミックの性質に応じたテクスチャ
- 加速床：加速方向を視覚的に判別できるテクスチャ

### テクスチャ描画の工夫

OpenGLの `GL_REPEAT` を利用し、壁のサイズに応じて画像を繰り返し描画しています。

`Wall` クラスの `setTexture()` では、テクスチャの種類と繰り返し単位（`tileSize`）を指定できるようにしました。

これにより、壁の大きさごとに画像を用意することなく、同じ素材を異なるサイズの壁に再利用できる構成にしています。

また、画像の背景を透明化する処理も実装しました。

画像の外周から連続する白色または黒色に近い領域を探索し、その部分のみを透明化することで、画像内部の同系色まで誤って削除することを防いでいます。

これらの処理を `Texture.cpp` にまとめ、画像の読み込み・描画処理をゲーム本体から分離しています。

## 制作について

本作品は、C/C++とOpenGL・GLUTを使用して個人で開発した2Dアクションゲームです。

「壁を利用して上へ進む」というコンセプトをもとに、プレイヤーの移動・ジャンプ処理から、壁との衝突判定、ステージギミック、カメラ制御、UI、サウンド、ランキング機能まで、一つのゲームとして完成させることを目標に制作しました。

開発では、特にプレイヤーと複数の壁が接触する際の衝突判定や、特殊な壁ギミックの挙動調整に苦労しました。問題が発生した際には、原因を切り分け、処理の順序や判定条件を見直しながら改善を重ねました。

また、一通り遊べる状態になった後も開発を継続しています。

機能追加によって複雑になったコードを見直し、プレイヤー・壁・ステージ・音声・ランキングなどの処理をクラス化・ファイル分割することで、保守性と拡張性の向上に取り組みました。

さらに、壁・床のテクスチャ化によるグラフィックの改善や、当たり判定の可視化・テレポートなどのデバッグ機能を追加し、ゲームの完成度と開発効率の両面から改良を進めています。

今後も、ゲームとしての面白さだけでなく、コードの可読性や設計、機能追加のしやすさを意識しながら、継続的にブラッシュアップしていきます。

## 今後の開発予定

本作品は、一通りプレイできる状態まで完成していますが、保守性・拡張性の向上や、新たな機能の実装に向けて継続的に開発を進めています。

### 1. ステージデータの外部ファイル化

現在、ステージ内の壁の配置や種類、移動範囲、テクスチャなどの情報は、主に `Stage.cpp` 内で直接定義しています。

今後は、これらの情報をJSON形式などの外部ファイルで管理する構成への変更を予定しています。

これにより、ソースコードを変更・再ビルドすることなく、壁の配置やギミックの設定を変更できるようにすることを目指しています。

### 2. ステージエディタの実装

ステージデータの外部ファイル化を行った後、壁やギミックを視覚的に配置・編集できるステージエディタの実装を目指しています。

- 壁・床の配置、移動、サイズ変更
- 壁の種類やテクスチャの設定
- 移動壁の速度・移動範囲などの設定
- ステージデータの保存・読み込み

これにより、ステージ制作やギミックの動作確認を効率化し、より多様なステージを制作しやすい開発環境を整えていきたいと考えています。
